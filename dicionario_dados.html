2. Visao geral do banco de dados

O banco atende uma unidade da academia que funciona 24 horas, em quatro turnos (madrugada, manha, tarde e noite). Ele cobre cadastro de alunos, planos e matriculas, treinos, aulas coletivas com check-in, comunicacao entre turnos, estoque de materiais e chamados de manutencao. Sao 12 entidades.

Convencao Definicao
SGBD MySQL 8 (InnoDB)
Codificacao utf8mb4_0900_ai_ci
Prefixos ID_ identificador, NM_ nome, DT_ data, CD_ codigo, QT_ quantidade, TP_ tipo/categoria, IN_ indicador booleano, DS_ descricao/texto livre, VL_ valor monetario
Notacao da composicao @ identificador, + elementos obrigatorios, ( ) opcional, [ | ] escolha entre alternativas, n{ }m iteracao
Legenda de origem Consolidado (README + HTML) consta nos dois documentos. a validar o grupo precisa confirmar.

Todos os valores de exemplo sao ficticios e servem apenas para ilustrar a estrutura dos atributos.

4. Dicionario detalhado das entidades

ALUNO

Cliente contratante; entidade central para acesso, cobranca e treinos. Consolidado (README + HTML)

Composicao: = @ID_ALUNO + NM_ALUNO + ID_CPF + NM_EMAIL + DT_NASCIMENTO + (DS_FOTO_PERFIL) + (DS_BIOMETRIA_FACIAL) + IN_ATIVO

Atributo Tipo Obrigatorio Observacao
ID_ALUNO integer Sim (PK) Identificador interno
NM_ALUNO varchar(120) Sim Nome completo
ID_CPF varchar(11) Sim (unico) Usado na busca pela recepcao
NM_EMAIL varchar(100) Sim Login no app e contato com SAC
DT_NASCIMENTO date Sim Validacao de idade/contrato
DS_FOTO_PERFIL varchar(255) Nao Pode ser cadastrada depois
DS_BIOMETRIA_FACIAL text Nao Valida em outras unidades
IN_ATIVO boolean Sim Muda com inadimplencia prolongada

Indices: PK em ID_ALUNO; indices secundarios em ID_CPF e NM_ALUNO.

Regras relacionadas: RN02, RN06 (ver secao 6)

A RN06 fala em anexar informacoes de saude ao cadastro do aluno, mas nenhum atributo desta entidade guarda esse anexo (ver I06).

PLANO

Modalidade comercial contratada, separada do cadastro do aluno para preservar o historico financeiro. Consolidado (README + HTML)

Composicao: = @ID_PLANO + NM_PLANO + [TP_RECORRENTE | TP_NAO_RECORRENTE] + VL_MENSALIDADE + IN_ATIVO

Atributo Tipo Obrigatorio Observacao
ID_PLANO integer Sim (PK) -
NM_PLANO varchar(60) Sim Ex.: "Mensal", "Black" a validar: o exemplo "Black" nao aparece na entrevista (ver I08)
TP_RECORRENTE / TP_NAO_RECORRENTE varchar(20) Sim Cobranca automatica ou avulsa a validar: nome do atributo difere do modelo logico (ver I04)

IN_ATIVO boolean Sim Disponivel para nova adesao

Regras relacionadas: nenhuma regra numerada do README cita esta entidade (ver secao 6)

6. Regras de negocio relacionadas as entidades

Codigo Regra Entidades relacionadas
RN01 O cancelamento de plano so ocorre por solicitacao formal via SAC. MATRICULA
RN02 Inadimplencia por periodo prolongado (segundo o entrevistado, cerca de 60 dias) cancela o plano automaticamente e bloqueia a catraca. MATRICULA, ALUNO
RN03 O spinning tem limite fixo de 19 vagas por horario. AULA_COLETIVA, CHECKIN_AULA
RN04 Personal trainers externos so podem atuar mediante cadastro ativo e pagamento de taxa mensal. Nenhuma entidade deste dicionario (ver I03)
RN05 Recepcao e professores so visualizam os ultimos 4 digitos do cartao do aluno (conformidade com a LGPD). MATRICULA
RN06 Informacoes de saude e limitacoes fisicas sao anexadas ao cadastro em formato digital (PDF/imagem). ALUNO, TREINO (ver I06)
RNF03 Requisito nao funcional: o historico de treinos deve ser preservado mesmo apos o desligamento do professor que os criou. TREINO, FUNCIONARIO

7. Observacoes sobre inconsistencias

Nada abaixo foi corrigido por conta propria: as informacoes foram preservadas como estavam e cada ponto precisa ser confirmado pelo grupo. As referencias ao modelo logico dizem respeito ao diagrama feito no dbdesigner.net, que nao e um dos dois documentos analisados.

ID Assunto O que foi encontrado O que confirmar
I01 Entidades no README O README (secoes 5 e 6) descreve 8 entidades; o HTML tem 12. Atualizar o README com ITEM_TREINO, UNIDADE, ESTOQUE_MATERIAL e CHAMADO_MANUTENCAO.
I02 UNIDADE em AULA_COLETIVA No modelo logico, AULA_COLETIVA tem ID_UNIDADE. No README e no HTML nao tem, e so ESTOQUE_MATERIAL referencia UNIDADE. Confirmar se AULA_COLETIVA deve ter ID_UNIDADE.
I03 PERSONAL_TRAINER A RN04 cita personal trainers externos e o modelo logico tem a tabela PERSONAL_TRAINER, mas ela nao esta no README nem no HTML. Confirmar se a entidade entra no dicionario e com quais atributos.
I04 Nomes de atributos README e HTML usam rotulos descritivos (Status, Papel, Turno, TP_RECORRENTE / TP_NAO_RECORRENTE). O modelo logico usa TP_STATUS, TP_PAPEL, TP_TURNO e TP_RECORRENCIA. Definir o nome final de cada atributo.
I05 TREINO e ITEM_TREINO TREINO ainda tem a linha NM_EXERCICIO, QT_SERIES, QT_REPETICOES, e ITEM_TREINO guarda os mesmos atributos. A composicao do README tambem mantem o grupo dentro de TREINO. Confirmar se a linha sai de TREINO. Ela foi mantida para nao perder informacao.
I06 RN06 e o modelo A RN06 fala em anexar PDF ou imagem ao cadastro do aluno, mas o unico campo de saude e DS_OBSERVACAO_MEDICA (texto) em TREINO. Definir onde o anexo e guardado.
I07 RF08 e TP_MATERIAL O RF08 cita itens promocionais, mas as categorias de TP_MATERIAL sao so LIMPEZA, HIGIENE e EQUIPAMENTO. Confirmar se falta uma categoria.
I08 Valores sem origem na entrevista Exemplos como "Black" e "Unidade Central", itens como toalhas e halteres, as categorias de TP_MATERIAL e os status do chamado nao aparecem na entrevista. Confirmar ou trocar por valores da academia.
I09 Notacao de cardinalidade No README, o par (min,max) aparece do lado oposto ao usual. Exemplo: ALUNO (1,1) - possui - (1,N) MATRICULA, embora um aluno tenha varias matriculas. Confirmar a notacao usada no DER.
I10 Composicao das novas entidades O README nao traz a composicao formal (= @ID + ...) de ITEM_TREINO, UNIDADE, ESTOQUE_MATERIAL e CHAMADO_MANUTENCAO. Definir as composicoes.
I11 Numeracao do README A numeracao do README pula do item 6 para o 7 (Justificativa Tecnica), sem a secao do DER. Nao afeta o dicionario. Conferir se a secao do DER foi removida de proposito.
