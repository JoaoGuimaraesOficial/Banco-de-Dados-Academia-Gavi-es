2. Visão geral do banco de dados

O banco contempla o gerenciamento de alunos, planos, matrículas, pagamentos e notas fiscais demonstrativas, funcionários, treinos, exercícios, aulas coletivas, check-ins, unidades, ocorrências de turno, chamados de manutenção e estoque de materiais. O modelo implementado possui 14 entidades.

Convenção Definição
SGBD MySQL 8.0.46 (InnoDB)
Banco de dados academia_gavioes
Codificação utf8mb4, com collation utf8mb4_0900_ai_ci
Prefixos ID_ identificador; NM_ nome; DT_ data; CD_ código; NR_ número; QT_ quantidade; TP_ tipo/categoria/status; IN_ indicador; DS_ descrição; VL_ valor monetário.
Notação da composição @ identificador; + atributo obrigatório; ( ) atributo opcional.

4. Dicionário detalhado das entidades

ALUNO

Cadastro do aluno, utilizado como referência para matrículas, treinos e participação em aulas.

Composição: @ID_ALUNO + NM_ALUNO + ID_CPF + NM_EMAIL + DT_NASCIMENTO + (DS_FOTO_PERFIL) + (DS_BIOMETRIA_FACIAL) + IN_ATIVO

Atributo Tipo Obrigatório Observação
ID_ALUNO int Sim (PK, AUTO_INCREMENT) Identificador interno do aluno.
NM_ALUNO varchar(120) Sim Nome completo do aluno.
ID_CPF varchar(11) Sim (UNIQUE) CPF armazenado sem pontuação; não pode se repetir.
NM_EMAIL varchar(100) Sim E-mail de contato do aluno.
DT_NASCIMENTO date Sim Data de nascimento.
DS_FOTO_PERFIL varchar(255) Não Caminho ou referência do arquivo da foto de perfil.
DS_BIOMETRIA_FACIAL text Não Campo destinado ao registro ou referência dos dados de biometria facial.
IN_ATIVO tinyint(1) Sim (DEFAULT 1) Indicador de cadastro ativo: 1 para ativo e 0 para inativo.

Índices e restrições: PK em ID_ALUNO; UNIQUE em ID_CPF; índice IDX_ALUNO_NM_ALUNO em NM_ALUNO; CHECK para aceitar somente 0 ou 1 em IN_ATIVO.

PLANO

Plano comercial que pode ser contratado por meio de uma matrícula.

Composição: @ID_PLANO + NM_PLANO + TP_RECORRENCIA + VL_MENSALIDADE + IN_ATIVO

Atributo Tipo Obrigatório Observação
ID_PLANO int Sim (PK, AUTO_INCREMENT) Identificador do plano.
NM_PLANO varchar(60) Sim Nome comercial do plano.
TP_RECORRENCIA varchar(20) Sim Tipo de recorrência: recorrente ou não recorrente.
VL_MENSALIDADE decimal(10,2) Sim Valor associado ao plano; deve ser maior que zero.
IN_ATIVO tinyint(1) Sim (DEFAULT 1) Indicador de disponibilidade: 1 para ativo e 0 para inativo.

Restrições: CHECK para VL_MENSALIDADE maior que zero; CHECK para os valores permitidos em TP_RECORRENCIA e para IN_ATIVO igual a 0 ou 1.

MATRICULA (entidade associativa entre ALUNO e PLANO)

Vincula um aluno a um plano e registra o período e a situação da matrícula.

Composição: @ID_MATRICULA + ID_ALUNO + ID_PLANO + DT_INICIO + (DT_FIM) + TP_STATUS + (CD_ULTIMOS_DIGITOS_CARTAO)

Atributo Tipo Obrigatório Observação
ID_MATRICULA int Sim (PK, AUTO_INCREMENT) Identificador da matrícula.
ID_ALUNO int Sim (FK) Referencia ALUNO(ID_ALUNO).
ID_PLANO int Sim (FK) Referencia PLANO(ID_PLANO).
DT_INICIO date Sim Data de início do contrato.
DT_FIM date Não Data de encerramento; pode permanecer NULL enquanto não houver data final definida.
TP_STATUS varchar(20) Sim Situação: pago, pendente, inadimplente ou cancelado.
CD_ULTIMOS_DIGITOS_CARTAO varchar(4) Não Armazena somente os quatro últimos dígitos do cartão, quando informados.

Restrições: FKs para ALUNO e PLANO; CHECK para os status permitidos; CHECK para garantir que DT_FIM seja NULL ou igual/posterior a DT_INICIO.

PAGAMENTO

Registra cobranças e pagamentos associados a uma matrícula. O status diferencia pagamentos confirmados daqueles que permanecem pendentes.

Composição: @ID_PAGAMENTO + ID_MATRICULA + DT_PAGAMENTO + VL_PAGAMENTO + TP_FORMA_PAGAMENTO + TP_STATUS

Atributo Tipo Obrigatório Observação
ID_PAGAMENTO int Sim (PK, AUTO_INCREMENT) Identificador do registro de pagamento.
ID_MATRICULA int Sim (FK) Referencia MATRICULA(ID_MATRICULA).
DT_PAGAMENTO date Sim Data registrada para o pagamento ou cobrança. Nos registros pendentes da massa de teste, representa a data de referência da cobrança, não a confirmação do recebimento.
VL_PAGAMENTO decimal(10,2) Sim Valor registrado; deve ser maior que zero.
TP_FORMA_PAGAMENTO varchar(30) Sim Forma registrada: PIX, dinheiro, cartão de crédito ou cartão de débito.
TP_STATUS varchar(30) Sim Situação do registro: pago ou pendente.

Restrições: FK para MATRICULA; CHECK para valor maior que zero, formas de pagamento e status permitidos.

Observação: a estrutura atual utiliza um único campo de data. Para distinguir formalmente vencimento da cobrança e data efetiva de recebimento, seria necessário acrescentar campos específicos ao modelo.

NOTA_FISCAL

Armazena registros demonstrativos de notas fiscais associados aos pagamentos confirmados. No escopo deste projeto acadêmico, os dados são fictícios e não representam emissão fiscal oficial.

Composição: @ID_NOTA_FISCAL + ID_PAGAMENTO + NR_NOTA_FISCAL + (NR_SERIE) + (CD_VERIFICACAO) + DT_EMISSAO + VL_SERVICO + DS_SERVICO + TP_STATUS + (DS_ARQUIVO_PDF)

Atributo Tipo Obrigatório Observação
ID_NOTA_FISCAL int Sim (PK, AUTO_INCREMENT) Identificador interno da nota fiscal.
ID_PAGAMENTO int Sim (FK, UNIQUE) Referencia PAGAMENTO(ID_PAGAMENTO). A restrição UNIQUE permite no máximo uma nota fiscal associada a cada pagamento.
NR_NOTA_FISCAL varchar(30) Sim (UNIQUE) Número identificador da nota; não pode se repetir. Na massa de teste, recebe numeração fictícia com prefixo TESTE-.
NR_SERIE varchar(10) Não Série atribuída ao registro demonstrativo.
CD_VERIFICACAO varchar(60) Não Código demonstrativo de verificação; não corresponde a uma validação fiscal real.
DT_EMISSAO datetime Sim Data e horário registrados como emissão.
VL_SERVICO decimal(10,2) Sim Valor do serviço; deve ser maior que zero.
DS_SERVICO varchar(255) Sim Descrição do serviço associado ao pagamento, incluindo o plano na massa de teste.
TP_STATUS varchar(20) Sim (DEFAULT 'pendente') Situação do registro: emitida, cancelada ou pendente.
DS_ARQUIVO_PDF varchar(255) Não Caminho ou referência do arquivo PDF, quando houver. Não é preenchido na massa de teste atual.

Índices e restrições: PK em ID_NOTA_FISCAL; FK para PAGAMENTO; UNIQUE em ID_PAGAMENTO e NR_NOTA_FISCAL; CHECK para VL_SERVICO maior que zero e para os status permitidos.

Os registros inseridos pelo script utilizam números e códigos de teste. Portanto, não devem ser apresentados como documentos fiscais válidos.

FUNCIONARIO

Cadastro dos funcionários, com identificação e função exercida na academia.

Composição: @ID_FUNCIONARIO + NM_FUNCIONARIO + ID_CPF + TP_PAPEL + IN_ATIVO

Atributo Tipo Obrigatório Observação
ID_FUNCIONARIO int Sim (PK, AUTO_INCREMENT) Identificador do funcionário.
NM_FUNCIONARIO varchar(120) Sim Nome completo.
ID_CPF varchar(11) Sim (UNIQUE) CPF armazenado sem pontuação; não pode se repetir.
TP_PAPEL varchar(20) Sim Função cadastrada: recepção, professor, gerente ou financeiro.
IN_ATIVO tinyint(1) Sim (DEFAULT 1) Indicador de vínculo ativo: 1 para ativo e 0 para inativo.

Restrições: UNIQUE em ID_CPF; CHECK para os papéis permitidos e para IN_ATIVO igual a 0 ou 1.

TP_PAPEL identifica a função do funcionário, mas o script atual não implementa controle de permissões de acesso por cargo. As FKs de TREINO e AULA_COLETIVA também não verificam, sozinhas, se o funcionário indicado possui o papel de professor.

TREINO

Ficha de treino vinculada a um aluno e a um funcionário indicado como professor.

Composição: @ID_TREINO + ID_ALUNO + ID_PROFESSOR + DT_CRIACAO + DT_VALIDADE + (DS_OBSERVACAO_MEDICA)

Atributo Tipo Obrigatório Observação
ID_TREINO int Sim (PK, AUTO_INCREMENT) Identificador da ficha de treino.
ID_ALUNO int Sim (FK) Referencia ALUNO(ID_ALUNO).
ID_PROFESSOR int Sim (FK) Referencia FUNCIONARIO(ID_FUNCIONARIO), indicando o funcionário responsável pela ficha.
DT_CRIACAO date Sim Data de criação da ficha.
DT_VALIDADE date Sim Data de validade da ficha; deve ser igual ou posterior à data de criação.
DS_OBSERVACAO_MEDICA text Não Observações relacionadas a limitações ou cuidados físicos informados para o aluno.

Restrições: FKs para ALUNO e FUNCIONARIO; CHECK para DT_VALIDADE maior ou igual a DT_CRIACAO.

ITEM_TREINO (itens e exercícios da ficha de treino)

Exercícios que compõem uma ficha de treino.

Composição: @ID_ITEM_TREINO + ID_TREINO + NM_EXERCICIO + QT_SERIES + QT_REPETICOES + (DS_CARGA)

Atributo Tipo Obrigatório Observação
ID_ITEM_TREINO int Sim (PK, AUTO_INCREMENT) Identificador do item de treino.
ID_TREINO int Sim (FK) Referencia TREINO(ID_TREINO).
NM_EXERCICIO varchar(100) Sim Nome do exercício.
QT_SERIES int Sim Quantidade de séries; deve ser maior que zero.
QT_REPETICOES int Sim Quantidade de repetições; deve ser maior que zero.
DS_CARGA varchar(30) Não Descrição da carga ou duração, conforme o exercício.

Restrições: FK para TREINO; CHECK para QT_SERIES e QT_REPETICOES maiores que zero.

UNIDADE

Cadastro das unidades da academia.

Composição: @ID_UNIDADE + NM_UNIDADE + DS_ENDERECO

Atributo Tipo Obrigatório Observação
ID_UNIDADE int Sim (PK, AUTO_INCREMENT) Identificador da unidade.
NM_UNIDADE varchar(100) Sim Nome da unidade.
DS_ENDERECO varchar(255) Sim Endereço da unidade.

AULA_COLETIVA

Aulas em grupo, com horário, instrutor, unidade e limite de vagas.

Composição: @ID_AULA + ID_INSTRUTOR + ID_UNIDADE + NM_MODALIDADE + DT_HORARIO + QT_LIMITE_VAGAS

Atributo Tipo Obrigatório Observação
ID_AULA int Sim (PK, AUTO_INCREMENT) Identificador da aula.
ID_INSTRUTOR int Sim (FK) Referencia FUNCIONARIO(ID_FUNCIONARIO), indicando o funcionário responsável pela aula.
ID_UNIDADE int Sim (FK) Referencia UNIDADE(ID_UNIDADE).
NM_MODALIDADE varchar(60) Sim Modalidade da aula, como spinning, boxe ou muay thai.
DT_HORARIO datetime Sim Data e horário programados para a aula.
QT_LIMITE_VAGAS int Sim Limite de vagas; deve ser maior que zero.

Restrições: FKs para FUNCIONARIO e UNIDADE; CHECK para QT_LIMITE_VAGAS maior que zero.

O CHECK valida que o limite cadastrado seja positivo, mas o script não impede automaticamente que a quantidade de check-ins ultrapasse esse limite. A consulta de auditoria A01 identifica essa situação.

CHECKIN_AULA (entidade associativa entre ALUNO e AULA_COLETIVA)

Registra a participação ou presença de um aluno em uma aula coletiva.

Composição: @ID_CHECKIN + ID_AULA + ID_ALUNO + DT_REALIZACAO

Atributo Tipo Obrigatório Observação
ID_CHECKIN int Sim (PK, AUTO_INCREMENT) Identificador do check-in.
ID_AULA int Sim (FK) Referencia AULA_COLETIVA(ID_AULA).
ID_ALUNO int Sim (FK) Referencia ALUNO(ID_ALUNO).
DT_REALIZACAO datetime Sim Data e horário em que o check-in foi registrado.

Índices e restrições: FKs para AULA_COLETIVA e ALUNO; UNIQUE composto em (ID_AULA, ID_ALUNO), impedindo mais de um registro do mesmo aluno para a mesma aula.

OCORRENCIA_TURNO

Registra recados, problemas e pendências identificados pelos funcionários durante os turnos.

Composição: @ID_OCORRENCIA + ID_FUNCIONARIO_AUTOR + DT_REGISTRO + TP_TURNO + DS_MENSAGEM + IN_RESOLVIDO

Atributo Tipo Obrigatório Observação
ID_OCORRENCIA int Sim (PK, AUTO_INCREMENT) Identificador da ocorrência.
ID_FUNCIONARIO_AUTOR int Sim (FK) Referencia FUNCIONARIO(ID_FUNCIONARIO), identificando quem registrou a ocorrência.
DT_REGISTRO datetime Sim Data e horário do registro.
TP_TURNO varchar(20) Sim Turno: madrugada, manhã, tarde ou noite.
DS_MENSAGEM text Sim Descrição do recado, problema ou pendência.
IN_RESOLVIDO tinyint(1) Sim (DEFAULT 0) Indicador de resolução: 0 para não resolvido e 1 para resolvido.

Restrições: FK para FUNCIONARIO; CHECK para os turnos permitidos e para IN_RESOLVIDO igual a 0 ou 1.

CHAMADO_MANUTENCAO

Registra solicitações de manutenção abertas pelos funcionários.

Composição: @ID_CHAMADO + ID_FUNCIONARIO_ABERTURA + DT_ABERTURA + DS_PROBLEMA + TP_STATUS

Atributo Tipo Obrigatório Observação
ID_CHAMADO int Sim (PK, AUTO_INCREMENT) Identificador do chamado.
ID_FUNCIONARIO_ABERTURA int Sim (FK) Referencia FUNCIONARIO(ID_FUNCIONARIO), identificando quem abriu a solicitação.
DT_ABERTURA datetime Sim Data e horário de abertura.
DS_PROBLEMA text Sim Descrição do problema ou defeito identificado.
TP_STATUS varchar(20) Sim Situação: aberto, em andamento ou concluído.

Restrições: FK para FUNCIONARIO; CHECK para os status permitidos.

ESTOQUE_MATERIAL

Registra materiais e suas quantidades em cada unidade da academia.

Composição: @ID_MATERIAL + ID_UNIDADE + NM_MATERIAL + TP_MATERIAL + QT_ESTOQUE

Atributo Tipo Obrigatório Observação
ID_MATERIAL int Sim (PK, AUTO_INCREMENT) Identificador do registro de material.
ID_UNIDADE int Sim (FK) Referencia UNIDADE(ID_UNIDADE), indicando onde o material está armazenado.
NM_MATERIAL varchar(100) Sim Nome ou identificação do material.
TP_MATERIAL varchar(50) Sim Categoria ou tipo do material.
QT_ESTOQUE int Sim Quantidade registrada; não pode ser negativa.

Restrições: FK para UNIDADE; CHECK para QT_ESTOQUE maior ou igual a zero.

6. Regras de integridade implementadas

Tabela Regra implementada no SQL
ALUNO IN_ATIVO deve ser 0 ou 1.
PLANO VL_MENSALIDADE deve ser maior que zero; TP_RECORRENCIA deve ser 'recorrente' ou 'não recorrente'; IN_ATIVO deve ser 0 ou 1.
FUNCIONARIO TP_PAPEL deve ser 'recepção', 'professor', 'gerente' ou 'financeiro'; IN_ATIVO deve ser 0 ou 1.
MATRICULA TP_STATUS deve ser 'pago', 'pendente', 'inadimplente' ou 'cancelado'; DT_FIM deve ser NULL ou maior/igual a DT_INICIO.
PAGAMENTO VL_PAGAMENTO deve ser maior que zero; forma e status devem pertencer aos valores permitidos no CHECK.
NOTA_FISCAL VL_SERVICO deve ser maior que zero; TP_STATUS deve ser 'emitida', 'cancelada' ou 'pendente'.
TREINO DT_VALIDADE deve ser maior ou igual a DT_CRIACAO.
ITEM_TREINO QT_SERIES e QT_REPETICOES devem ser maiores que zero.
AULA_COLETIVA QT_LIMITE_VAGAS deve ser maior que zero.
OCORRENCIA_TURNO TP_TURNO deve ser um dos quatro turnos permitidos; IN_RESOLVIDO deve ser 0 ou 1.
CHAMADO_MANUTENCAO TP_STATUS deve ser 'aberto', 'em andamento' ou 'concluído'.
ESTOQUE_MATERIAL QT_ESTOQUE deve ser maior ou igual a zero.

As regras acima representam as restrições declaradas no script SQL. Elas não significam que todas as regras operacionais da academia estejam automatizadas: por exemplo, o controle de permissões por cargo e o bloqueio de check-ins quando o limite de vagas é atingido não são implementados diretamente pelas restrições atuais.
